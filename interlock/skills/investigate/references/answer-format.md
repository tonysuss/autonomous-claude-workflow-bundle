# Answer format

Write for a senior engineer new to this code: enough to build a working model, not annotated source. Drop sections that do not apply.

## Overview
One or two paragraphs: what this is, what it does, why it exists. A reader who stops here should know whether to read on.

## Key concepts
The types, functions and terms needed to follow the rest, one line each.

## How it works
The longest section. What triggers it, what happens step by step, where data goes, where the decisions are. Name files and functions (`exporter.py:14`, `export()`) so the reader knows where to look. Prose, not pseudocode. Add a small diagram only when several components talk to each other.

## Where things live
The few files someone would open first.

## Why it is this way
Only for motivation questions. Each claim carries its confidence tier and its source (commit, PR, comment). Say what you searched when you found nothing.

## Evidence
Every command you ran to confirm behavior, with the lines of output that matter.

## Gotchas
Non-obvious behavior and traps. Skip if there are none.
