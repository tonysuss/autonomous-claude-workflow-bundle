`kvconf get app.conf app.title` now prints `Issue #42: retry`; I changed `parseValue` in `parser.go`, which was cutting the line at the first `#` before it looked at quotes.

- **Cause:** `parseValue` stripped the comment first, so it cut `"Issue #42: retry"` at the `#`. That left an unterminated quote and the error.
- **Fix:** a value that starts with `"` is now read up to its closing quote. A `#` inside is kept, `\"` and `\\` are unescaped, and a `# ...` comment after the closing quote is allowed. Unquoted values still end at the first `#`.
- **Behaviour change:** text after a closing quote that isn't a comment, such as `"a" b`, is now an error ("unexpected text after closing quote"). I added that on my own. Before, that kind of value was either mangled or reported as unterminated.
- **Checks:** I added `TestQuotedValues` to `parser_test.go`, covering a `#` in quotes, an unquoted `#`, a comment after the quote, and the escapes. `go test ./...` passes, and interlock ran both the repro and regression checks on the patched tree and they passed.
