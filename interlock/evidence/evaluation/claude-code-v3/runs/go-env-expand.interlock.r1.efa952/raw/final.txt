`Parse` and `Load` now expand `${NAME}`, `${NAME:-fallback}` and `$$` in unquoted and double-quoted values. An unset variable with no fallback fails with `kvconf: line N: undefined variable "NAME"`. `go test ./...` passes, including a new `TestExpand`, and `sh checks/expand.sh` passes when run through interlock.

- **API:** I added `ParseOptions{NoExpand}` and `ParseWithOptions`. I also added `LoadWithOptions`, which you didn't ask for. The CLI needs it to pass the option to `Load`.
- **CLI:** `kvconf get` and `kvconf dump` accept `--no-expand` before the file name. I only checked it by hand on `get` (it printed `${DATA_ROOT}/data`), not on `dump`, and no test covers it.
- **Unterminated `${`:** this wasn't in the spec. I made it a parse error (`unterminated ${ in value`) rather than keeping it literally.
- **Files changed:** `parser.go`, `config.go`, `cmd/kvconf/main.go`, `parser_test.go` and `README.md`.
- **Claims recorded:** I recorded claims for `expand` (observed), `regression` (tested) and `spec` (tested). `expand` and `spec` still need the independent verifier.
